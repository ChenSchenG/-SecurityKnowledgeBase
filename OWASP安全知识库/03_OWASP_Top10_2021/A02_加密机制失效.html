A02:2021 - 加密机制失效（Cryptographic Failures）

CRITICAL 排名第2

Cryptographic Failures（原名 Sensitive Data Exposure）在 2021 年从第 3 位上升到第 2 位。名称的变更反映了问题的本质——不是数据"暴露"了，而是保护数据的加密机制失效了。这是导致敏感数据泄露的根本原因（root cause），而非症状。

核心概念

加密机制失效指的是：在保护敏感数据的过程中，由于未使用加密、使用了不安全的加密算法、密钥管理不当、或加密实现错误，导致数据面临被窃取或篡改的风险。这涵盖了数据传输和存储的全生命周期。

加密机制失效的攻击面总览： ┌─────────────────────────────────────────────────────────────────────┐ │ 敏感数据生命周期 │ ├─────────────────────────────────────────────────────────────────────┤ │ │ │ [用户输入] ──→ [传输中] ──→ [处理中] ──→ [存储中] ──→ [备份/归档] │ │ │ │ │ │ │ │ ▼ ▼ ▼ ▼ │ │ HTTP明文传输 内存中明文 明文存储数据库 备份未加密 │ │ 弱TLS版本 日志记录敏感 弱哈希算法 云存储公开 │ │ 证书问题 数据 无加密 传输未加密 │ │ 中间人攻击 缓存敏感数据 密钥与数据同存 │ │ │ └─────────────────────────────────────────────────────────────────────┘

1. 概述与背景

1.1 为什么排名第2

加密机制失效位列第 2 的原因：

  • 影响面极广：几乎所有应用都处理敏感数据，加密问题普遍存在
  • 后果极其严重：直接导致用户隐私泄露、合规违规、经济损失
  • 检测困难：加密实现错误通常不影响功能正常运行，难以在测试中发现
  • 历史教训惨痛：大量真实泄露事件（Equifax、Yahoo、Adobe）根因都是加密失效

1.2 与旧名称的区别

对比2017: Sensitive Data Exposure2021: Cryptographic Failures
关注点症状——数据被暴露了根因——加密机制出了问题
思维方式"数据泄露了怎么办""如何确保加密正确保护数据"
防御方向被动（发现泄露后补救）主动（在设计阶段确保加密正确）

1.3 关键问题自查

判断你的系统是否存在加密机制失效
  • 是否有数据以明文形式传输？（包括内网传输）
  • 是否使用了旧的或脆弱的加密算法/协议？
  • 是否使用了默认加密密钥、弱密钥，或密钥未轮换？
  • 是否没有强制加密？（如缺少 HSTS 头）
  • 服务器证书是否有效并被正确验证？
  • 密码是否使用了专用密码哈希函数存储？
  • 是否使用了不安全的随机数生成器？
  • 是否使用了已被废弃的哈希函数（如 MD5、SHA1）？
  • 是否使用了已被废弃的填充方法（如 PKCS#1 v1.5）？
  • 加密错误信息是否可被利用（如 Padding Oracle）？

最小化原则

不收集、不存储不必要的敏感数据是最好的保护。你无法泄露你没有的数据。在设计阶段就要问："我们真的需要存储这个数据吗？"

3. 传输中的数据（Data in Transit）

3.5 安全的 TLS 配置（Nginx 示例）

# ✅ Nginx 安全 TLS 配置
server {
    listen 443 ssl http2;
    server_name example.com;

    # 证书配置
    ssl_certificate     /etc/ssl/certs/example.com.pem;
    ssl_certificate_key /etc/ssl/private/example.com.key;

    # 仅允许 TLS 1.2 和 1.3
    ssl_protocols TLSv1.2 TLSv1.3;

    # 安全的 cipher suite（服务器优先）
    ssl_prefer_server_ciphers on;
    ssl_ciphers 'ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384';

    # HSTS - 强制浏览器使用 HTTPS（包含子域名，预加载）
    add_header Strict-Transport-Security "max-age=63072000; includeSubDomains; preload" always;

    # OCSP Stapling - 加速证书验证
    ssl_stapling on;
    ssl_stapling_verify on;

    # DH 参数（至少 2048 位）
    ssl_dhparam /etc/ssl/dhparam-4096.pem;

    # Session 配置
    ssl_session_timeout 1d;
    ssl_session_cache shared:SSL:50m;
    ssl_session_tickets off;  # 禁用 session tickets（影响前向保密）
}

# HTTP 重定向到 HTTPS
server {
    listen 80;
    server_name example.com;
    return 301 https://$server_name$request_uri;
}

4. 存储中的数据（Data at Rest）

4.1 密码存储的演进

密码存储方式的安全性演进： Level 0: 明文存储（最危险） ┌─────────────────────────────────┐ │ user_id │ username │ password │ │ 1 │ alice │ P@ssw0rd │ ← 数据库泄露 = 所有密码泄露 │ 2 │ bob │ 123456 │ └─────────────────────────────────┘ Level 1: 简单哈希（MD5/SHA1） ┌─────────────────────────────────────────────────┐ │ user_id │ username │ password_hash │ │ 1 │ alice │ 5f4dcc3b5aa765d61d8327... │ ← MD5("password") │ 2 │ bob │ e10adc3949ba59abbe56e0... │ ← MD5("123456") └─────────────────────────────────────────────────┘ 问题：彩虹表可以直接反查！ Level 2: 加盐哈希（Salt + SHA256） ┌──────────────────────────────────────────────────────────────┐ │ user_id │ username │ salt │ password_hash │ │ 1 │ alice │ a3f2b8c1... │ SHA256(salt + password) │ │ 2 │ bob │ 7e9d4f2a... │ SHA256(salt + password) │ └──────────────────────────────────────────────────────────────┘ 问题：SHA256 太快了！GPU 可以每秒尝试数十亿次 Level 3: 专用密码哈希（bcrypt/scrypt/Argon2）✅ 推荐 ┌──────────────────────────────────────────────────────────┐ │ user_id │ username │ password_hash │ │ 1 │ alice │ $2b$12$LJ3m4ov... 4.2 为什么 MD5/SHA1 不适合密码存储

特性MD5/SHA1/SHA256bcrypt/scrypt/Argon2
设计目的快速计算文件摘要密码哈希（故意慢）
计算速度极快（GPU: 数十亿次/秒）故意慢（~100ms/次）
内置盐值❌ 需要自己管理✅ 自动生成和存储
成本可调❌ 固定速度✅ 可增加迭代/内存
抗 GPU❌ 高度可并行✅ 内存硬函数
抗 ASIC❌Argon2: ✅
 
# 破解速度对比（Hashcat + RTX 4090）：
# MD5:        ~160 Billion (1600亿) hashes/second
# SHA1:       ~50 Billion hashes/second
# SHA256:     ~22 Billion hashes/second
# bcrypt(12): ~100 Thousand hashes/second  ← 慢了 22万倍！
# Argon2:     更慢（依赖内存带宽）

# 实际含义：
# 8位小写字母密码 (26^8 ≈ 2000亿组合)
# MD5:    ~1.3 秒即可穷举
# bcrypt: ~23 天
# 加上大小写+数字+符号 → bcrypt 需要数千年

4.3 正确的密码哈希实现

# ✅ Python - 使用 bcrypt
import bcrypt

def hash_password(password: str) -> str:
    """哈希密码 - 注册/修改密码时调用"""
    # work factor=12 意味着 2^12 = 4096 轮迭代
    salt = bcrypt.gensalt(rounds=12)
    hashed = bcrypt.hashpw(password.encode('utf-8'), salt)
    return hashed.decode('utf-8')

def verify_password(password: str, hashed: str) -> bool:
    """验证密码 - 登录时调用"""
    return bcrypt.checkpw(
        password.encode('utf-8'),
        hashed.encode('utf-8')
    )

# 使用示例
stored_hash = hash_password("MySecretP@ss!")
# 结果: $2b$12$LJ3m4ov1z3G8RzYq... (60字符，包含算法、cost、盐值、哈希)

is_valid = verify_password("MySecretP@ss!", stored_hash)  # True
is_valid = verify_password("WrongPass", stored_hash)      # False
# ✅ Python - 使用 Argon2（当前最推荐）
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

# 配置参数
ph = PasswordHasher(
    time_cost=3,        # 迭代次数
    memory_cost=65536,  # 内存使用 64MB
    parallelism=4,      # 并行线程数
    hash_len=32,        # 输出哈希长度
    salt_len=16         # 盐值长度
)

def hash_password(password: str) -> str:
    """使用 Argon2id 哈希密码"""
    return ph.hash(password)

def verify_password(password: str, hash: str) -> bool:
    """验证密码，支持自动 rehash"""
    try:
        ph.verify(hash, password)
        # 检查是否需要 rehash（参数升级时）
        if ph.check_needs_rehash(hash):
            return True  # 调用方应更新存储的哈希
        return True
    except VerifyMismatchError:
        return False

# 使用示例
hash = hash_password("MySecretP@ss!")
# 结果: $argon2id$v=19$m=65536,t=3,p=4$randomsalt$hashvalue
# ✅ Python - 使用 scrypt（标准库自带）
import hashlib
import os

def hash_password_scrypt(password: str) -> str:
    """使用 scrypt 哈希密码"""
    salt = os.urandom(32)  # 32字节随机盐
    key = hashlib.scrypt(
        password.encode(),
        salt=salt,
        n=2**14,   # CPU/内存成本参数 (16384)
        r=8,       # 块大小
        p=1,       # 并行参数
        dklen=64   # 输出密钥长度
    )
    # 将盐值和哈希一起存储
    return salt.hex() + ':' + key.hex()

def verify_password_scrypt(password: str, stored: str) -> bool:
    """验证 scrypt 哈希的密码"""
    salt_hex, key_hex = stored.split(':')
    salt = bytes.fromhex(salt_hex)
    expected_key = bytes.fromhex(key_hex)
    key = hashlib.scrypt(
        password.encode(),
        salt=salt,
        n=2**14, r=8, p=1, dklen=64
    )
    # 使用常量时间比较防止时序攻击
    return hmac.compare_digest(key, expected_key)
密码哈希选择指南（2024+）
  • 首选 Argon2id：2015 年 Password Hashing Competition 冠军，抗 GPU/ASIC，可调节时间和内存成本
  • 次选 bcrypt：久经考验（1999年），广泛支持，但有 72 字节密码长度限制
  • 备选 scrypt：内存硬函数，但参数调优较复杂
  • 绝不使用：MD5、SHA1、SHA256（即使加盐）、自制哈希方案

4.4 其他存储数据的加密

# ✅ 数据库字段级加密（使用 AES-256-GCM）
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
import os

class FieldEncryptor:
    """用于加密数据库中的敏感字段（如身份证号、银行卡号）"""

    def __init__(self, key: bytes):
        """key 应从 KMS 或安全的密钥存储获取，32字节 = AES-256"""
        assert len(key) == 32, "AES-256 requires 32-byte key"
        self.aesgcm = AESGCM(key)

    def encrypt(self, plaintext: str) -> str:
        """加密字段值，返回 Base64 编码的密文"""
        nonce = os.urandom(12)  # 96-bit nonce，每次加密必须不同
        ciphertext = self.aesgcm.encrypt(
            nonce,
            plaintext.encode('utf-8'),
            None  # associated data (可选)
        )
        # nonce + ciphertext 一起存储
        import base64
        return base64.b64encode(nonce + ciphertext).decode('utf-8')

    def decrypt(self, encrypted: str) -> str:
        """解密字段值"""
        import base64
        data = base64.b64decode(encrypted)
        nonce = data[:12]
        ciphertext = data[12:]
        plaintext = self.aesgcm.decrypt(nonce, ciphertext, None)
        return plaintext.decode('utf-8')

# 使用示例
key = os.urandom(32)  # 实际应从 KMS 获取
encryptor = FieldEncryptor(key)

# 加密身份证号
encrypted_id = encryptor.encrypt("110101199001011234")
# 存入数据库: "aGVsbG8gd29ybGQ..."

# 解密
original_id = encryptor.decrypt(encrypted_id)
# "110101199001011234"

5.2 ECB 模式的问题

ECB（Electronic Codebook）模式是最简单的分组密码模式，但对于大多数场景来说是不安全的。

ECB 模式 vs CBC 模式： ECB (Electronic Codebook) - 不安全： ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 明文块1 │ │ 明文块2 │ │ 明文块3 │ └────┬─────┘ └────┬─────┘ └────┬─────┘ │ │ │ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ AES加密 │ │ AES加密 │ │ AES加密 │ ← 相同密钥，独立加密 └────┬─────┘ └────┬─────┘ └────┬─────┘ │ │ │ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 密文块1 │ │ 密文块2 │ │ 密文块3 │ └──────────┘ └──────────┘ └──────────┘ 问题：相同的明文块 → 相同的密文块！ → 可以看出数据的模式（著名的 ECB 企鹅图） → 可以重排密文块 → 可以替换密文块 CBC (Cipher Block Chaining) - 更好： ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 明文块1 │ │ 明文块2 │ │ 明文块3 │ └────┬─────┘ └────┬─────┘ └────┬─────┘ │ │ │ IV→ ⊕ ┌──→⊕ ┌──→⊕ ← 每块与前一密文块XOR │ │ │ │ │ ▼ │ ▼ │ ▼ ┌──────────┐ │ ┌──────────┐ │ ┌──────────┐ │ AES加密 │ │ │ AES加密 │ │ │ AES加密 │ └────┬─────┘ │ └────┬─────┘ │ └────┬─────┘ │──────────┘ │──────────┘ │ ▼ ▼ ▼ ┌──────────┐ ┌──────────┐ ┌──────────┐ │ 密文块1 │ │ 密文块2 │ │ 密文块3 │ └──────────┘ └──────────┘ └──────────┘ 推荐：使用 GCM 模式（同时提供加密和认证）

7.2 场景二：彩虹表攻击（Rainbow Table Attack）

# 彩虹表原理：
# 预先计算所有可能密码的哈希值，构建"哈希→明文"映射表
# 时间-空间权衡：牺牲存储空间换取破解时间

# 彩虹表规模示例：
# - 所有 8 位小写字母+数字 (36^8 = 2.8万亿) 的 MD5: 约 25TB
# - 所有 6 位可打印 ASCII (95^6 = 7350亿) 的 MD5: 约 6TB
# - 常见密码字典 (数亿条) 的 MD5: 几 GB

# 在线彩虹表查询（无需自己计算）：
# - crackstation.net
# - cmd5.com
# - hashes.org

# 演示：MD5 哈希反查
import hashlib

# 模拟攻击者拥有的彩虹表（实际会大得多）
rainbow_table = {}
common_passwords = [
    "123456", "password", "12345678", "qwerty", "abc123",
    "monkey", "1234567", "letmein", "trustno1", "dragon",
    "baseball", "iloveyou", "master", "sunshine", "ashley",
    "michael", "shadow", "123123", "654321", "superman"
]

# 构建彩虹表
for pwd in common_passwords:
    h = hashlib.md5(pwd.encode()).hexdigest()
    rainbow_table[h] = pwd

# 破解泄露的哈希
leaked_hashes = [
    "e10adc3949ba59abbe56e057f20f883e",  # ?
    "5f4dcc3b5aa765d61d8327deb882cf99",  # ?
    "d8578edf8458ce06fbc5bb76a58c5ca4",  # ?
]

for h in leaked_hashes:
    if h in rainbow_table:
        print(f"[CRACKED] {h} → {rainbow_table[h]}")
    else:
        print(f"[FAILED]  {h} → not in table")

# 输出：
# [CRACKED] e10adc3949ba59abbe56e057f20f883e → 123456
# [CRACKED] 5f4dcc3b5aa765d61d8327deb882cf99 → password
# [CRACKED] d8578edf8458ce06fbc5bb76a58c5ca4 → qwerty
为什么加盐（Salt）能防御彩虹表

盐值是在哈希前拼接到密码上的随机字符串。每个用户使用不同的盐值，因此即使两个用户使用相同密码，哈希结果也不同。攻击者需要为每个盐值单独构建彩虹表，使预计算攻击变得不可行。但加盐并不能阻止针对性的暴力破解——所以仍然需要使用慢哈希函数。

7.3 场景三：Padding Oracle 攻击

Padding Oracle 攻击原理： 背景：CBC 模式 + PKCS#7 填充 + 服务器泄露填充是否有效 PKCS#7 填充规则： 如果最后一个块差 N 字节，则填充 N 个值为 N 的字节 差1字节: ... 01 差2字节: ... 02 02 差3字节: ... 03 03 03 整块: ... 10 10 10 10 10 10 10 10 10 10 10 10 10 10 10 10 攻击过程： 1. 攻击者发送修改过的密文给服务器 2. 服务器尝试解密： - 填充正确 → 返回 200 OK（或正常处理） - 填充错误 → 返回 500 Error / "Padding Error" 3. 通过观察服务器对不同密文的不同响应（Oracle） 攻击者可以逐字节推断出明文！ 每个字节最多尝试 256 次 一个 16 字节块：最多 256 × 16 = 4096 次请求即可解密！ 受影响的真实系统： - ASP.NET (CVE-2010-3332) - "Padding Oracle" 名称的由来 - Java Server Faces - Ruby on Rails Cookie 加密 - 各种自定义加密方案
# Padding Oracle 攻击演示（简化）
# 攻击者无需知道密钥，仅通过观察服务器响应即可解密！

import requests

def padding_oracle_attack(ciphertext, block_size=16):
    """
    简化的 Padding Oracle 攻击逻辑
    前提：服务器对填充错误返回不同的错误码
    """
    blocks = [ciphertext[i:i+block_size]
              for i in range(0, len(ciphertext), block_size)]

    plaintext = b''

    for block_idx in range(1, len(blocks)):
        intermediate = bytearray(block_size)
        decrypted_block = bytearray(block_size)

        for byte_idx in range(block_size - 1, -1, -1):
            padding_value = block_size - byte_idx

            # 构造恶意前缀块
            prefix = bytearray(block_size)
            for k in range(byte_idx + 1, block_size):
                prefix[k] = intermediate[k] ^ padding_value

            # 遍历所有可能的字节值
            for guess in range(256):
                prefix[byte_idx] = guess
                # 发送 prefix + target_block 给服务器
                test_cipher = bytes(prefix) + blocks[block_idx]

                response = requests.get(
                    f"https://target.com/api/decrypt?data={test_cipher.hex()}"
                )
                if response.status_code != 500:  # 填充正确！
                    intermediate[byte_idx] = guess ^ padding_value
                    decrypted_block[byte_idx] = (
                        intermediate[byte_idx] ^ blocks[block_idx-1][byte_idx]
                    )
                    break

        plaintext += bytes(decrypted_block)

    return plaintext

8.3 完整的加密工具类实现（Python）

"""
secure_crypto.py - 安全加密工具类
满足 OWASP 加密要求的完整实现
"""
import os
import hmac
import hashlib
import base64
import secrets
from typing import Tuple

from cryptography.hazmat.primitives.ciphers.aead import AESGCM
from cryptography.hazmat.primitives.kdf.pbkdf2 import PBKDF2HMAC
from cryptography.hazmat.primitives import hashes
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError


class SecureCrypto:
    """安全加密工具类"""

    # ==================== 密码哈希 ====================

    @staticmethod
    def hash_password(password: str) -> str:
        """
        使用 Argon2id 哈希密码
        返回值包含算法、参数、盐值、哈希 - 可直接存入数据库
        """
        ph = PasswordHasher(
            time_cost=3,        # 迭代次数
            memory_cost=65536,  # 64 MB 内存
            parallelism=4,      # 4 线程
            hash_len=32,
            salt_len=16
        )
        return ph.hash(password)

    @staticmethod
    def verify_password(password: str, hash_str: str) -> bool:
        """验证密码是否匹配"""
        ph = PasswordHasher(
            time_cost=3,
            memory_cost=65536,
            parallelism=4
        )
        try:
            return ph.verify(hash_str, password)
        except VerifyMismatchError:
            return False

    # ==================== 对称加密 ====================

    @staticmethod
    def generate_key(bit_length: int = 256) -> bytes:
        """生成密码学安全的随机密钥"""
        return AESGCM.generate_key(bit_length=bit_length)

    @staticmethod
    def encrypt(plaintext: bytes, key: bytes,
                associated_data: bytes = None) -> bytes:
        """
        AES-256-GCM 加密
        返回: nonce (12 bytes) + ciphertext + tag (16 bytes)
        """
        aesgcm = AESGCM(key)
        nonce = os.urandom(12)  # 96-bit nonce
        ciphertext = aesgcm.encrypt(nonce, plaintext, associated_data)
        return nonce + ciphertext  # nonce 放在前面

    @staticmethod
    def decrypt(data: bytes, key: bytes,
                associated_data: bytes = None) -> bytes:
        """
        AES-256-GCM 解密
        输入: nonce (12 bytes) + ciphertext + tag (16 bytes)
        """
        aesgcm = AESGCM(key)
        nonce = data[:12]
        ciphertext = data[12:]
        return aesgcm.decrypt(nonce, ciphertext, associated_data)

    # ==================== 密钥派生 ====================

    @staticmethod
    def derive_key_from_password(password: str,
                                  salt: bytes = None) -> Tuple[bytes, bytes]:
        """
        从密码派生加密密钥（用于加密文件等场景）
        不要用于密码存储！密码存储请用 hash_password()
        """
        if salt is None:
            salt = os.urandom(16)

        kdf = PBKDF2HMAC(
            algorithm=hashes.SHA256(),
            length=32,
            salt=salt,
            iterations=600000,  # OWASP 2023 推荐值
        )
        key = kdf.derive(password.encode())
        return key, salt

    # ==================== 安全 Token ====================

    @staticmethod
    def generate_token(length: int = 32) -> str:
        """生成 URL 安全的随机 token"""
        return secrets.token_urlsafe(length)

    @staticmethod
    def generate_otp(digits: int = 6) -> str:
        """生成安全的一次性验证码"""
        max_val = 10 ** digits
        code = secrets.randbelow(max_val)
        return str(code).zfill(digits)

    # ==================== 安全比较 ====================

    @staticmethod
    def safe_compare(a: str, b: str) -> bool:
        """
        常量时间字符串比较 - 防止时序攻击
        无论字符串是否匹配，执行时间都相同
        """
        return hmac.compare_digest(a.encode(), b.encode())

    # ==================== HMAC ====================

    @staticmethod
    def compute_hmac(data: bytes, key: bytes) -> str:
        """计算 HMAC-SHA256"""
        return hmac.new(key, data, hashlib.sha256).hexdigest()

    @staticmethod
    def verify_hmac(data: bytes, key: bytes,
                    expected_mac: str) -> bool:
        """验证 HMAC（常量时间比较）"""
        computed = hmac.new(key, data, hashlib.sha256).hexdigest()
        return hmac.compare_digest(computed, expected_mac)


# ==================== 使用示例 ====================

if __name__ == "__main__":
    crypto = SecureCrypto()

    # 1. 密码哈希
    password = "MyS3cur3P@ssw0rd!"
    hashed = crypto.hash_password(password)
    print(f"Hash: {hashed}")
    print(f"Verify: {crypto.verify_password(password, hashed)}")

    # 2. 数据加密
    key = crypto.generate_key()
    message = b"Sensitive data: SSN 123-45-6789"
    encrypted = crypto.encrypt(message, key)
    decrypted = crypto.decrypt(encrypted, key)
    print(f"Decrypted: {decrypted.decode()}")

    # 3. 生成安全 token
    token = crypto.generate_token()
    print(f"Token: {token}")

    # 4. 生成验证码
    otp = crypto.generate_otp(6)
    print(f"OTP: {otp}")

8.6 应急响应：密钥泄露后的处理

密钥/凭据泄露应急响应流程
  1. 立即轮换：作废泄露的密钥/凭据，生成新的
  2. 评估影响：确定泄露的时间范围，哪些数据可能被访问
  3. 检查日志：查看泄露密钥是否已被使用（API 调用、异常登录）
  4. 从历史中清除：如果提交到 Git，使用 BFG Repo Cleaner 清除历史
  5. 通知受影响方：按法规要求通知用户和监管机构
  6. 修复根因：为什么密钥会泄露？加固防护措施
