A05:2021 - 安全配置错误 (Security Misconfiguration)

HIGH 排名第5

90% 的应用都被测试出存在某种形式的配置错误。随着云服务和微服务架构的普及，配置错误的攻击面越来越大。这是最常见但也是最容易预防的漏洞类别之一。

核心问题

安全配置错误不是代码层面的 bug，而是部署和运维层面的疏忽。完美的代码部署在错误配置的环境上，同样是脆弱的。

1. 概述

1.1 配置错误的来源

安全配置错误的攻击面： ┌─────────────────────────────────────────────────────────┐ │ 应用技术栈 │ ├─────────────────────────────────────────────────────────┤ │ │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │ │ │ 应用代码 │ │ 框架配置 │ │ Web服务器 │ │ 数据库 │ │ │ │ DEBUG=True│ │ CORS: * │ │ 目录列表 │ │ 无密码 │ │ │ └──────────┘ └──────────┘ └──────────┘ └────────┘ │ │ │ │ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────┐ │ │ │ 操作系统 │ │ 容器配置 │ │ 云服务 │ │ 网络 │ │ │ │ 默认用户 │ │ root运行 │ │ S3公开 │ │ 端口暴露│ │ │ └──────────┘ └──────────┘ └──────────┘ └────────┘ │ │ │ │ 每一层都可能存在配置错误！ │ └─────────────────────────────────────────────────────────┘

4. 安全头 (Security Headers)

4.1 必备安全头清单

Header作用推荐值
Content-Security-Policy防止XSS、数据注入根据应用定制
X-Content-Type-Options防止MIME嗅探nosniff
X-Frame-Options防止ClickjackingDENY 或 SAMEORIGIN
Strict-Transport-Security强制HTTPSmax-age=31536000; includeSubDomains
X-XSS-Protection浏览器XSS过滤(遗留)0 (现代浏览器用CSP替代)
Referrer-Policy控制Referer信息泄露strict-origin-when-cross-origin
Permissions-Policy控制浏览器功能权限按需配置camera、mic等
Cache-Control防止敏感数据缓存no-store, no-cache(敏感页面)

4.2 CSP (Content Security Policy) 配置

# CSP 基本配置示例
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-abc123' https://cdn.example.com;
  style-src 'self' 'unsafe-inline';
  img-src 'self' data: https:;
  font-src 'self' https://fonts.googleapis.com;
  connect-src 'self' https://api.example.com;
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;

# CSP 指令说明：
# default-src:    默认策略（其他未指定时的回退）
# script-src:     允许的脚本来源
# style-src:      允许的样式来源
# img-src:        允许的图片来源
# connect-src:    允许的AJAX/WebSocket连接目标
# frame-ancestors: 谁能嵌入本页面（替代X-Frame-Options）
# 'nonce-xxx':    允许含特定nonce的内联脚本
# 'self':         同源
# 'unsafe-inline': 允许内联（尽量避免）

# Nginx 配置安全头
server {
    add_header X-Content-Type-Options "nosniff" always;
    add_header X-Frame-Options "DENY" always;
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header Content-Security-Policy "default-src 'self'; script-src 'self'" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
}

4.3 安全头检测工具

# 在线检测
# https://securityheaders.com
# https://observatory.mozilla.org

# 命令行检测
curl -I https://target.com | grep -iE "(x-frame|x-content|strict|csp|referrer)"

# Python 脚本批量检测
import requests

REQUIRED_HEADERS = [
    'X-Content-Type-Options',
    'X-Frame-Options',
    'Strict-Transport-Security',
    'Content-Security-Policy',
]

def check_headers(url):
    resp = requests.get(url)
    missing = []
    for header in REQUIRED_HEADERS:
        if header.lower() not in [h.lower() for h in resp.headers]:
            missing.append(header)
    return missing

5. 详细错误信息泄露

5.1 错误信息中的敏感数据

错误信息泄露的危害链： 详细错误响应 → ├─ Stack Trace → 代码路径、框架版本、第三方库 ├─ SQL Error → 表名、列名、查询语句 ├─ 文件路径 → 操作系统类型、部署路径、用户名 ├─ 版本号 → 已知漏洞利用 (CVE匹配) └─ 配置信息 → 数据库连接串、API Key 真实泄露示例： HTTP/1.1 500 Internal Server Error --- Traceback (most recent call last): File "/home/deploy/app/views/user.py", line 45, in get_user user = db.execute("SELECT * FROM users WHERE id=%s", user_id) File "/usr/lib/python3.9/site-packages/mysql/connector.py", line 234 raise DatabaseError(msg) mysql.connector.errors.DatabaseError: 1064: You have an error in your SQL syntax near ''1'' at line 1 Connection: mysql://appuser:P@ssw0rd123@10.0.1.5:3306/production_db ↑泄露用户名 ↑泄露密码 ↑泄露内网IP ↑泄露库名

5.2 安全的错误处理

# ✅ 生产环境错误处理最佳实践

# Python Flask
@app.errorhandler(500)
def internal_error(error):
    # 记录详细错误到日志（供开发排查）
    app.logger.error(f"Internal Error: {error}", exc_info=True)
    # 返回通用错误给用户（不泄露细节）
    return {"error": "Internal server error", "code": 500}, 500

@app.errorhandler(404)
def not_found(error):
    return {"error": "Resource not found", "code": 404}, 404

# Java Spring Boot
# application.properties
server.error.include-stacktrace=never
server.error.include-message=never
server.error.include-binding-errors=never

# Node.js Express
app.use((err, req, res, next) => {
    // 记录详细错误
    logger.error(err.stack);
    // 返回通用错误
    res.status(500).json({
        error: 'Something went wrong',
        requestId: req.id  // 用于追踪，不泄露细节
    });
});

# Nginx 自定义错误页
error_page 500 502 503 504 /50x.html;
location = /50x.html {
    root /usr/share/nginx/html;
    internal;
}
